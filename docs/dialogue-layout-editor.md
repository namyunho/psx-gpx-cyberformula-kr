# 통합 폰트 번역 편집기

## 목적

`scripts/dialogue_layout_editor.py`는 그래픽 에셋에 직접 새겨진 문자를
제외하고, 확인된 모든 게임 폰트 출력 문자열을 한 화면에서 검토하는 로컬
GUI다. 기본 통합 작업공간은 다음 항목을 불러온다.

| 분류 | 편집 행 | 정본 번역 JSON |
|---|---:|---|
| 본편 직접 포인터 대사 | 5,783 | `work/translations/disc1-dialogue-ko-candidate.json` |
| 무포인터 선택·대사 | 84 | `data/translations/disc1-pointerless-pages-u00-u21-ko.json` |
| 추가 분기·순차 대사 | 295 | `data/translations/disc1-unindexed-font-ko.json` |
| 추가 경기 대사 | 334 | `data/translations/disc1-unindexed-font-ko.json` |
| 미니게임 대사·요리 런타임 단어·결과 합성 조각 | 331 | `data/translations/disc1-special-screen-ko.json` |
| 추가 미니게임 분기·결과 | 74 | `data/translations/disc1-unindexed-font-ko.json` |
| 코스 설명 | 57 | `data/translations/disc1-special-screen-ko.json` |
| 머신 설정 설명·순차 분기 | 32 | `data/translations/disc1-special-screen-ko.json` |
| 저장·불러오기 메시지 | 27 | `data/translations/disc1-unindexed-font-ko.json` |
| 폰트 렌더링 UI 리터럴 | 4 | `data/translations/disc1-ui-ko.json` |
| 고정 주인공명·화자명 | 36 | `data/translations/disc1-character-names.json` |

무포인터 원본 스트림 2개는 각각 두 편집 구간을 가지므로 JSON 엔트리 수보다
편집 행이 2개 많다. 표시 글리프가 하나도 없는 제어 전용 센티널 1개는
목록에서 제외한다. 이름 입력용 한자·가나·영문 팔레트와 가변 런타임 버퍼는
번역 문장이 아니므로 보호하고, 그래픽 버튼·라벨·타이틀은 그래픽 작업
범위로 남긴다. 현재 통합 목록은 총 7,059행이다. 추가 workset 806개 중
최종전 미러 70개와 짧은 경기 미러 6개는 각 정본에서 자동 생성되므로 독립
편집 행을 만들지 않는다. 나머지 추가 730개는 정적 소비자
계열과 원본 바이트를 확인했지만 실제 색인 진입 경로와 재삽입 정책은 아직
실행 검증 전이므로 편집기 상태에도 이를 명시한다.

편집기는 각 안정 ID를 추출 workset과 결합해 `speaker_style`, `audio`,
`page_end`·`stream_end` 같은 실제 이벤트 스트림 제어를 읽기 전용으로
표시한다. 제어코드는 한국어 문자열에 복사하지 않는다. ROM이나 빌드
이미지는 수정하지 않는다.

통합 작업공간 자체를 별도 JSON으로 만들지 않는다. 저장하면 변경된 한국어
필드만 위 표의 정본 파일로 되돌리고, 다른 필드·엔트리 순서·안정 ID는
보호한다. 편집기를 연 뒤 정본 파일이 외부에서 변경되었으면 덮어쓰기를
거부한다.

기본 검증 안전 슬롯 자료는 다음 파일이다.

```text
work/analysis/disc1-dialogue-safe-slots.json
```

이 자료는 본편 5,783건에 대해 원본 ALLBIN과 보호 workset을 전수 대조한
고정 원위치 바이트 한도이자 unit별 원본 대사 스트림 총량의 기준선이다.
무포인터·특수 화면·UI에는 확인된 원본 스트림 바이트 크기를 보수적인
참고 한도로 표시하며, 공용 재배치나 확장이 검증된 것으로 간주하지 않는다.
자세한 본편 경계 정책은
[대사별 검증 안전 슬롯](dialogue-safe-slots.md)을 참고한다.

## 실행

Homebrew Python 3.14에서는 Tk 모듈이 별도 패키지다.

```bash
brew install python-tk@3.14
python3 scripts/build_dialogue_safe_slots.py
.venv/bin/python scripts/dialogue_layout_editor.py
```

인자 없이 실행하면 통합 작업공간을 연다. 명시적으로 같은 동작을 요청하려면
`--all-font-text`를 사용할 수 있다.

macOS Finder에서는 저장소 최상위의 다음 파일을 더블클릭하면 된다.

```text
대사-편집기.command
```

실행기는 `.venv`, 여섯 정본 번역 JSON, 다섯 추출 workset과 원본 ALLBIN을
확인하고 본편 안전 슬롯 JSON/CSV를 최신 원본에서 다시 만든 뒤 통합
편집기를 연다. 첫 실행에서 macOS가 차단하면 Finder에서 파일을
Control-클릭한 뒤 `열기`를 선택한다.

특정 대사에서 시작:

```bash
.venv/bin/python scripts/dialogue_layout_editor.py \
  --entry-id disc1/allbin/u00/event_page/ref0000
```

기존처럼 한 JSON만 별도로 열기:

```bash
.venv/bin/python scripts/dialogue_layout_editor.py \
  --input work/translations/disc1-dialogue-chapters/disc1-dialogue-u00.json \
  --editable-field ko_reflowed
```

다른 보호 workset을 선택:

```bash
.venv/bin/python scripts/dialogue_layout_editor.py \
  --workset work/translations/disc1-dialogue.json
```

다른 안전 슬롯 자료를 선택:

```bash
.venv/bin/python scripts/dialogue_layout_editor.py \
  --safe-slots work/analysis/disc1-dialogue-safe-slots.json
```

GUI를 열지 않고 입력 구조와 항목별 레이아웃 초과 수를 확인:

```bash
.venv/bin/python scripts/dialogue_layout_editor.py --check
```

이 명령은 통합 행 수, 분류별 수량, 렌더러별 셀 프로필, 제어 셸·슬롯 연결
수와 현재 초과 건수를 JSON으로 출력한다.

2026-07-29 정본의 `--check` 기준은 다음과 같다.

| 항목 | 값 | 판정 |
|---|---:|---|
| 통합 편집 행 | 7,059 | 빈 번역 0 |
| 원문 줄바꿈 그대로의 화면 초과 | 110 | 추가 독립 항목 730개 초과 0, 기존 후보 수동 줄바꿈 검토 목록 |
| 재삽입 감사의 파생 17×3 배치 | 5,783/5,783 | 기계 배치 차단 0, 사람 검토 필요 |
| 개별 고정 슬롯 초과 | 1,724 | 공용 재배치 또는 축약 검토 |
| unit 공용 총량 초과 | 1 unit (`u24`, 2바이트) | 현재 저장 정본 기준, 다음 통합 빌드 전 축약 또는 검증된 공백 압축 필요 |
| 짧은 행 검토 후보 | 1,105 | 오류가 아닌 수동 검토 후보 |

편집기는 정본의 수동 줄바꿈을 그대로 보여 주고,
`audit_dialogue_reinsertion.py`는 별도 파생 reflow를 만든다. 따라서
편집기의 화면 초과 111건과 감사의 기계 배치 차단 0건은 서로 모순이 아니다.
파생 결과가 들어간다는 사실만으로 정본의 부자연스러운 단어 분할이나
띄어쓰기 제거가 승인되지는 않는다.

## 기능

- 분류 선택: 본편, 무포인터, 추가 순차, 추가 경기, 미니게임, 코스, 머신
  설정, 저장·불러오기, UI, 캐릭터 이름
- 항목별 실제 논리 셀 프로필과 반각 적용 예상 픽셀 폭 미리보기
- 고정 제어코드 스트림의 런타임 17열 자동 줄바꿈 미리보기와 수동 개행 차단
- 행별 논리 글리프 수·예상 픽셀 폭, 표시 글리프 합계와 초과 경고
- `한도 초과만` 필터와 초과 목록 안의 검색·이전·다음 이동
- `안전 슬롯 초과만` 필터와 개별 원본 슬롯 바이트 막대
- `유닛 총량 초과만` 필터와 unit 공용 사용량·잔여량 막대
- `6자 미만 행만` 필터로 불필요한 줄바꿈 검수 후보 분리
- ALLBIN·유닛 안전 시작/종료 주소와 보호 경계 종류 표시
- 원본 raw 값·마크업·보존 정책과 편집 결과의 인라인 스트림 표시
- 일본어 원문·안정 ID·상태·제한값 읽기 전용 표시
- 이전/다음 이동과 ID·원문·번역 검색
- 용어 찾기, 대상 미리보기와 현재 항목·분류·전체 일괄 바꾸기
- 현재 대사의 수동 편집과 Undo
- 띄어쓰기 경계만 사용하는 보수적 자동 배치
- 마지막 저장 상태로 엔트리 복원
- 통합 저장 시 변경된 정본 JSON만 백업·원자 교체
- 단일 JSON 모드의 저장과 다른 이름으로 저장

본문·대부분의 특수 화면은 17×3, 요리 런타임 단어는 17×1, 화자명은
6×1이다. UI의 1·3·4·6행 스트림과 무포인터 선택지는 원본 행 수를 정확히
보존한다. 행 수 고정 항목에는 줄 수를 줄이는 자동 배치를 적용하지 않으며,
행 수가 달라지면 저장을 거부한다.

반각 렌더러가 적용된 공백과 `!`, `(`, `)`, `,`, `.`, `?`는 미리보기에서
8px 진행 폭으로, 나머지 글리프는 14px 진행 폭으로 표시한다. 한 행의 원래
화면 폭은 `17×14=238px`이며 편집기 상단에는 `논리 글리프/열 수`와
`예상 px/238px`를 함께 표시한다. 이것은 화면상의 간격을 검토하기 위한
정보이며 17글리프 제한을 늘리지 않는다.

게임은 반각 문자가 섞여 화면 폭이 남아도 17번째 논리 글리프 뒤에서 자동으로
다음 행을 시작한다. 따라서 18개의 반각 공백처럼 238px보다 좁은 행도 여전히
17열 초과다. 반각 글리프 역시 저장 스트림에서는 기존과 같은 16비트 토큰
하나이므로 안전 슬롯과 unit 공용 바이트 계산도 줄어들지 않는다. 편집기의
자동 배치는 기존처럼 논리 글리프 수와 띄어쓰기 경계만 사용하며 번역문이나
줄바꿈을 반각 폭에 맞춰 자동 변경하지 않는다.

## 용어 찾기/바꾸기

상단의 `찾기/바꾸기` 버튼 또는 Windows/Linux의 `Ctrl+H`, macOS의
`Command+Option+F`로 용어 창을 연다. 다음 범위를 선택할 수 있다.

- 전체 폰트 문자열
- 본편 대사
- 무포인터 선택·대사
- 추가 분기·순차 대사
- 추가 경기 대사
- 미니게임
- 코스 설명
- 머신 설정
- 저장·불러오기
- 폰트 UI
- 캐릭터 이름

찾기는 정규식이 아닌 리터럴 문자열 비교다. 괄호·점·별표 같은 문장부호도
입력한 그대로 찾으며, 필요하면 영문 대소문자를 구분하지 않을 수 있다.
`대상 미리보기`는 변경될 안정 ID, 항목별 치환 횟수와 변경 전·후 문자열을
최대 30개까지 보여준다.

`모두 바꾸기`는 대상 항목 수, 실제 치환 횟수, 적용 범위와 일부 안정 ID를
다시 제시하고 사람의 확인을 받은 뒤에만 적용한다. 일본어 원문, raw 토큰,
제어코드, 안정 ID와 다른 보호 필드는 바꾸지 않는다. 결과는 즉시 정본
파일에 저장되지 않고 일반 편집과 같은 미저장 상태로 남는다.

`방금 일괄 변경 취소`는 마지막 한 번의 현재 항목 또는 일괄 변경을 통째로
되돌린다. 일괄 변경 뒤 같은 항목을 수동 수정했다면 수정 내용을 덮어쓰지
않고 자동 취소를 거부한다. 저장할 때는 기존 항목별 행·글리프·슬롯 검증을
그대로 적용하므로 용어를 바꿨다는 이유로 빌드 적격이 자동 부여되지는 않는다.

보수적 자동 배치는 기존 줄바꿈을 soft whitespace로 보고 단어 내용과 순서를
바꾸지 않는다. 현재 항목의 셀 프로필에 들어가는 배치 중 행 수를 먼저
최소화하고, 행 절반보다 짧은 줄을 줄인 뒤 길이 편차가 작은 후보를
제시한다. 단어를 쪼개야만
들어가는 문장은 자동 변경하지 않고 경고한다. 버튼을 누른 현재 엔트리에만
적용되며 저장 전 확인 창을 거친다.

`한도 초과만`은 고정 이름 토큰을 실제 표시명으로 확장한 뒤 현재 항목의
열·행 프로필을 위반하는 엔트리만 모아 보여준다.

- 표시 글리프 합계가 현재 열×행 용량보다 많음
- 어느 한 행이라도 현재 열 수보다 많음
- 명시적인 줄 수가 최대 행보다 많거나, 행 고정 항목의 행 수가 달라짐

`안전 슬롯 초과만`은 현재 재인코딩 예상 크기가 엔트리별 엄격 안전 슬롯
바이트보다 큰 대사만 모은다. 표시 글리프뿐 아니라 선두·후미 제어와 줄바꿈
제어도 각각 2바이트로 센다. 따라서 17×3에는 들어가지만 슬롯은 초과하는
대사와, 슬롯에는 들어가지만 화면 배치가 잘못된 대사는 서로 다를 수 있다.

개별 안전 슬롯 초과는 더 이상 곧바로 축약 사유가 아니다. 실행 검증을
통과한 `unit-shared-pool` 빌드는 같은 unit의 짧아진 대사에서 남은 바이트를
긴 대사에 재할당한다. 편집기의 두 번째 막대는 unit에 속한 모든 엔트리의
현재 예상 스트림 바이트를 원본 스트림 바이트 합계와 비교한다. 대사 사이의
무포인터 페이지와 이벤트 gap은 byte-exact 보호 대상이므로 공용 용량에
포함하지 않는다.

```text
개별 원본 슬롯  72B / 68B — 4B 초과 · 공용 재배치 필요
u00 공용       4,848B / 5,624B — 776B 공용 여유 · 실행 검증 완료
```

개별 슬롯은 초과해도 unit 총량이 남으면 재배치할 수 있다. 반대로 unit
총량을 1바이트라도 넘으면 해당 unit의 모든 대사 중 어디에서 용량을 줄일지
검토해야 하며 기본 빌드 차단 상태다. `u00`, `u21`은 동일 Track 1로 전체
진행 실행 검증을 통과했다. 다른 unit도 계산값은 표시하지만 전수 포인터
카탈로그와 실행 검증을 갖추기 전에는 `공용 재배치 미검증`으로 표시한다.

현재 비배포 전체 빌드는 `u27..u34` 8개 unit에
`--allow-unit-capacity-space-compaction`을 명시해 공백 266개만 제거하고
unit 총량을 맞췄다. 비공백 글리프와 제어 셸은 보존하며 결과는 제2장
종료까지 사용자 진행을 통과했다. 이것은 자연스러운 띄어쓰기 승인이나
배포 적격 판정이 아니다. 편집기에는 원문 후보를 그대로 남겨 어느 unit을
사람이 줄여야 하는지 계속 경고한다.

편집 중인 엔트리가 한도 안에 들어온 즉시 목록에서 사라지지는 않는다.
`목록 갱신`을 누르면 현재 편집값으로 초과 목록을 다시 계산한다. 목록의 `!`
표시는 화면 한도 초과, `B`는 개별 안전 슬롯 바이트 초과, `U`는 unit 공용
총량 초과, `~`는 짧은 행 후보, `*`는 저장하지 않은 변경을 뜻한다.

`6자 미만 행만`은 2행 이상의 대사에서 표시 글리프가 1~5개인 행을 하나라도
가진 엔트리를 모은다. 빈 행과 원래 한 줄뿐인 짧은 대사는 제외한다. 고정 이름
토큰은 실제 표시명으로 확장해 센다. `한도 초과만`과 함께 선택하면 두 조건을
모두 만족하는 엔트리만 표시한다.

짧은 행은 불필요한 줄바꿈을 찾기 위한 검수 후보일 뿐 오류 판정이 아니다.
편집기가 행을 자동으로 합치지는 않으므로 앞뒤 문장, 읽기 호흡과 17×3
미리보기를 확인한 뒤 사람이 줄바꿈을 수정한다.

## 확정 표시 제약

프로젝트의 본문 대사 한 페이지는 줄당 최대 17글리프, 최대 3줄로 제한한다.
unit에 저장 바이트가 남더라도 네 번째 줄은 허용하지 않는다. 따라서 다음
세 제약은 서로 대신할 수 없다.

1. 한 행이 17글리프 이하여야 한다.
2. 한 페이지가 3줄 이하여야 한다.
3. 개별 원본 슬롯은 넘을 수 있지만 unit 공용 총량은 넘을 수 없다.

새로 수정한 엔트리가 4줄이면 편집기 저장 자체를 거부한다. 한 행의 17글리프
초과나 unit 총량 초과는 여러 대사를 조정하는 중간 작업을 보존할 수 있도록
경고 상태로 저장할 수 있지만 `!` 또는 `U`가 남은 항목은 빌드 적격이 아니다.
주 빌드는 모든 17×3 위반을 실패로 처리한다. unit 총량도 기본적으로
실패시키며 위의 명시적 비배포 공백 축소 옵션만 별도 기록과 검증을 거쳐
허용한다. 의미를 자동 축약하거나 비공백 글리프·제어토큰 중간에서 자르지
않는다.

## 이벤트 스트림 제어

`실제 이벤트 스트림 제어 — 읽기 전용` 영역은 현재 대사가 재인코딩될 때
결합되는 제어 셸을 색상 칩과 함께 다음처럼 보여준다.

```text
바이트: 원본 스트림 68B · 검증 안전 슬롯 68B · 현재 예상 64B · 4B 미사용
슬롯 경계: ALLBIN 0x000054–0x000098 / unit 0x0054–0x0098 · 바로 다음 추출 대사 시작
선두 보호: 0x903F {speaker_style:03F} [preserve]
조판: 줄바꿈 2개 → 0xFFFB {align} [movable-layout-in-story-only]
후미 보호: 0x8000 {page_end} [preserve]
인라인 스트림: {speaker_style:03F}한국어{align}대사{page_end}
```

색상은 소비 역할을 나타낸다.

| 색상 | 역할 | 표시 글리프 |
|---|---|---:|
| 보라 | 화자·초상 상태 | 0 |
| 파랑 | 음성·음성 전환 | 0 |
| 주황 | `FFFB` 줄바꿈 | 0, 다음 행으로 이동 |
| 빨강 | 페이지·스트림 종료 | 0 |
| 회색 | 진행 속도·대기 같은 기타 제어 | 0 |
| 밝은 바탕 | 실제 표시 글리프 | 표시 문자 수만큼 |

17×3 미리보기의 세로 기준선은 14px짜리 원래 논리 셀을 나타내고, 실제
글리프 영역은 반각 8px·기본 14px 진행 폭으로 이어서 그린다. 명시적인
`FFFB`가 현재 행의 남은 화면 폭을 건너뛰면 주황색으로 채우고 오른쪽에
`↵ FFFB`를 표시한다. 제어토큰 없는 런타임 자동 줄바꿈은 `↵ AUTO 17`로
구분한다. 따라서 제어토큰이 글리프 칸을 직접 차지하지 않으면서도 다음
행으로 이동해 사용하지 못하게 만든 위치를 논리 글리프 수 및 화면 픽셀
폭과 분리해서 확인할 수 있다.

선두와 후미 제어는 원본 workset의 raw 토큰에서 가져오며 편집할 수 없다.
줄바꿈은 확인된 조판 토큰이므로 현재 한국어 줄바꿈에서 `0xFFFB`로 다시
계산한다. 화면에 인라인으로 보이더라도 후보 JSON에는 번역문만 저장한다.
빌드가 같은 안정 ID의 보호 workset을 결합하므로 제어코드를 `ko`에 다시
기입하면 중복 인코딩 위험이 생긴다.

현재 예상 바이트는 보호 셸, 표시 글리프와 줄바꿈을 합친 재인코딩 크기다.
첫 막대의 검증 안전 슬롯은 원본 ALLBIN의 같은 시작 주소에서 사용할 수 있는
개별 한도다. 초록은 사용량, 회색은 미사용, 주황은 공용 재배치가 필요한
개별 초과를 뜻한다. 두 번째 막대는 unit 전체의 원본 대사 스트림 총량과
현재 합계를 보여주며, 빨강은 unit 총량 초과를 뜻한다. 대사 사이 보호 gap과
다른 unit의 잔여량은 이 계산에 넣지 않는다.

편집기는 화면의 17×3 배치와 원본 이벤트 슬롯 바이트를 독립적으로 검사한다.
다만 초상화·인물명·분기 소비의 실행 시점까지 인증하지는 않으므로 ROM 삽입
감사와 실행 검증을 대신하지 않는다.

## 저장 안전성

통합 모드에서 저장하면 수정된 정본 파일마다 같은 디렉터리에 백업을 만든다.

```text
disc1-dialogue-ko-candidate.json.bak
disc1-special-screen-ko.json.bak
```

수정하지 않은 정본에는 백업이나 쓰기를 수행하지 않는다. 새 JSON은 임시
파일에 쓴 뒤 다시 파싱하고 원자적으로 교체한다. 여러 파일 저장 중 오류가
나면 이미 교체한 파일을 이번 백업으로 복원한다. 프로그램은 로드한 문서의
복사본에 연결된 한국어 필드만 대입하므로 엔트리 순서나 보호 필드를 편집할
수 없다. 통합 작업공간에는 `다른 이름으로 저장`을 제공하지 않는다.

편집 결과는 번역 후보일 뿐 자동으로 빌드 적격이 되지 않는다. 저장 후 기존
감사와 빌드를 다시 실행해야 한다.

```bash
.venv/bin/python scripts/audit_dialogue_reinsertion.py
```

## macOS·Tk 호환성 기록

Homebrew Python 3.14/Tk에서 실제 실행하며 다음 두 초기화 오류를 확인하고
회귀 검사 가능한 형태로 수정했다.

- `ttk.LabelFrame`은 `-textvariable` 옵션을 지원하지 않았다. 생성 시
  `text`를 쓰고 제목 변경 때 `configure(text=...)`로 갱신한다.
- 메타데이터 갱신 함수의 `profile` 지역 변수가 레이아웃 프로필을 unit
  저장 프로필로 덮어써 `UnitStorageProfile.columns` 접근 오류가 났다.
  레이아웃·unit 프로필 이름을 분리하고 표시 문자열 생성을 headless 함수로
  떼어 테스트한다.

이 수정 뒤 사용자가 `대사-편집기.command`로 통합 GUI가 열리는 것을
확인했다. Codex는 사용자 방침에 따라 GUI 자동 조작이나 Lua 실행으로
검증하지 않았다.
