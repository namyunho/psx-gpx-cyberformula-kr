# 반각 공백·문장부호 렌더러

## 목적과 범위

한국어 본문의 공백과 문장부호가 14픽셀 전각 간격을 차지해 문장이 성기게
보이는 문제를 줄인다. 적용 문자는 공백, `!`, `(`, `)`, `,`, `.`, `?` 일곱
종류다. 4bpp 작업 버퍼의 바이트 경계에 맞춰 이 문자들의 화면상 진행 폭만
14픽셀에서 8픽셀로 바꾼다.

이 변경은 번역 JSON, u16 글리프 코드, 명시적 `FFFB` 줄 경계, 17칸 논리
카운터와 제어 토큰을 수정하지 않는다. 이미 실행 검수한 줄바꿈과 이벤트 순서를
그대로 두고 화면 좌표만 왼쪽으로 당긴다. 따라서 반각화로 한 줄에 더 많은
논리 글리프를 자동 수용하거나 대사를 재배치하지는 않는다.

## 구현

`sub_80032704`를 원래 함수 범위 `0x80032704..0x800329B8` 안에서 armips로
재조립했다. 기본 글리프는 7바이트(14픽셀), 대상 글리프는 4바이트(8픽셀)를
진행한다. 대상 글리프 뒤에는 현재 행의 누적 목적지 보정을 3바이트씩 늘린다.
원래 논리 위치가 다음 행으로 바뀌거나 새 페이지의 위치가 0으로 돌아가면 보정을
초기화한다.

누적 상태는 매 페이지 `sub_8003229C`가 0으로 지우는 12KiB 임시 렌더 버퍼의
마지막 워드 `0x8002FFFC`를 사용한다. 대사 업로드 영역 밖의 임시 상태이며,
상주 코드·폰트 공간으로 취급하지 않는다. 이름 입력 경로는 기존 고정 폭을
유지하고, primary의 컨트롤러 아이콘 마스크 처리도 보정된 좌표에서 보존한다.

### 이름 치환 좌표 회귀 수정

초기 반각판은 `{name:surname}`·`{name:given}` 경로에서 누적 좌표 보정을
읽고 저장하는 처리까지 건너뛰었다. 이름 글리프 자체를 14px 전각으로 유지하는
조건과, 앞선 반각 글리프로 당겨진 현재 행 좌표를 이어받는 조건을 잘못 같은
분기로 묶은 것이다. 이름 앞에 공백이나 문장부호가 있으면 이름은 원래 좌표에
그려지고 이름 뒤 일반 글리프는 보정 좌표로 돌아와 서로 겹쳤다.

수정판은 이름 글리프에도 기존 누적 감소량을 적용하고, 이름을 그린 뒤 현재
논리 위치와 감소량을 다시 저장한다. 이름 글리프는 반각 후보 검사로 보내지
않으므로 각 글리프의 진행 폭은 계속 14px다. 현재 정본의 이름 치환 대사
116개 중 같은 행의 이름 앞에 반각 문자가 있는 직접 영향 후보 60개를 이
회귀 범위로 잡는다.

현재 일곱 글리프의 실제 잉크 범위는 모두 셀 x=0..7 안에 있어, 14×14 폰트
레코드는 바꾸지 않았다. `START.BIN`, `ALLBIN.BIN`, `OUTSIDE.BIN`과 대사
데이터는 직전 파일 빌드와 바이트 단위로 같다.

## 빌드와 검증

```bash
.venv/bin/python scripts/build_halfwidth_text_patch.py \
  --input-dir work/build/<complete-file-build> \
  --output-dir work/build/<halfwidth-file-build>
```

armips 출력은 `scripts/mips_disasm.py`로 다시 판독했다. 실행 파일 변경은
`SLPS_019.58 +0x2F04..+0x31B7` 안의 588바이트에만 있고 함수 다음 주소
`0x800329B8`을 침범하지 않는다. 직전 반각판과 비교하면 이름 상태 분기 명령
두 개의 4바이트만 다르다. MIPS load/branch delay 경고 없이 조립되며 이름
좌표 분기를 포함한 반각 렌더러 회귀 검사 3개를 통과했다.

2026-08-04 Disc 1·2 비배포 이미지는 동일한 파일 빌드에서 만들었고 각각 원본
크기, ISO root, 예상 변경 sector, Mode 2 Form 1 EDC/ECC와 재추출 해시 검증을
통과했다. 이 판에는 요리 미니게임 선택 버튼 8개와 편집한 타이틀도 포함된다.

| 대상 | Track 1 SHA-256 | 상태 |
|---|---|---|
| Disc 1 | `74117ee7b8eb8f5d01fb46297c4fd12ce2bf50e711c6053b62ca69746afa7e00` | 4+4 이름·그래픽 포함 정적 검증 통과, 실행 검증 필요 |
| Disc 2 | `2e5c702b4b0e7de33c71a9ef128e01c50089b41a4e61113fe23926bafed86f40` | 4+4 이름·그래픽 포함 정적 검증 통과, 실행 검증 필요 |

현재 작업 트리의 전체 230개 검사가 모두 통과했다. 두 이미지는 각 622개
변경 sector와 자체 포함 Track 2–4를 가지며 `dumpsxiso`로 CUE에서 다시 꺼낸
파일 해시도 최종 파일 빌드와 일치한다.

실행 검증에서는 일반 대사, 연속 공백·문장부호, 미니게임 설명, 이름 입력과
컨트롤러 아이콘을 확인한다. GUI 이동이나 Lua 실행은 사용자가 재현 위치를
준비한 뒤 별도 신호를 줄 때만 수행한다.
