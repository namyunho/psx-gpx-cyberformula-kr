# 저장 화면 한글화

저장·불러오기 문장 27개는 `ALLBIN.BIN` u39 글꼴 스트림이고, 슬롯의 경기명·
시간대·미사용 표기와 이름은 `SLPS_019.58`의 별도 메타데이터 및 동적 글리프
캐시를 사용한다. 확인 버튼 글자는 폰트 문자열이 아니라 `OUTSIDE.BIN`의 4bpp
그래픽이다.

## 슬롯 이름 표시

4+4 이름 입력 뒤 런타임 캐시는 한 슬롯마다 다음 여덟 글리프를 보유한다.

```text
성 4글리프 + 이름 4글리프
시 바 (빈칸) (빈칸) + 세 이 치 로
```

저장 목록의 좁은 이름 열에 8글리프를 모두 넣으면 오른쪽 챕터 열을 침범한다.
따라서 `scripts/build_save_screen_patch.py`는 각 슬롯 캐시의 뒤쪽 네 글리프, 즉
입력한 **이름만** 표시한다. 스트림은 검증된 `0x8004F320` 영역 안에서 끝내고
남은 바이트는 종단 토큰 뒤 0으로 채운다. 슬롯별 캐시 기준 코드는
`04D6`, `04DE`, `04E6`, `04EE`이며 실제 표시 코드는 각각 `base+4..base+7`이다.

현재 PCSX-Redux RAM 관측에서는 첫 슬롯의 `04D6..04DD`가
`시·바·빈칸·빈칸·세·이·치·로`와 일치했다. 정적 구조와 빌드는 검증했지만
게임 화면에서 이름 네 글자가 모두 보이는지는 새 이미지로 실행 확인해야 한다.

## 예·아니오 버튼

GPU primitive와 VRAM을 대조한 결과 확인 버튼은 다음 자산을 소비한다.

| 항목 | 값 |
|---|---|
| 저장 자산 | `OUTSIDE.BIN` unit 1 / child 4 |
| child 파일 오프셋 | `0x3668C` |
| 4bpp payload | `0x36694`; 업로드 폭 256 VRAM halfword = 1,024px |
| `예` 영역 | texture `(0,232)` 40×16px |
| `아니오` 영역 | texture `(40,232)` 40×16px |
| 런타임 tpage | `0x0008`, VRAM x=512, y=0 |
| CLUT | 선택 상태 `0x7D09`, 비선택 상태 `0x7D0A` |

업로드 헤더의 폭 256은 픽셀 수가 아니라 VRAM halfword 수다. 따라서 4bpp의
저장 행 간격은 `256×2=512`바이트이며 한 행에 1,024픽셀이 들어간다. 이를
128바이트 행으로 해석하면 목표 y=232가 실제 y=58에 기록되어 슬롯 사이의 공용
그래픽을 훼손한다.

올바른 행 간격으로 두 40×16 영역만 0으로 지운 뒤 Galmuri11 12px 글자를 중앙 배치한다. 인덱스
1은 밝은 본문, 인덱스 8은 1px 그림자에 사용한다. 상태별 기존 CLUT, 64×24
버튼 배경, 그 밖의 픽셀은 변경하지 않는다. 원본 `OUTSIDE.BIN` SHA-256과
수정 전 영역을 모두 확인하고, 빌드 매니페스트의 Expected Writes가 허용된 행
범위 밖 변경을 거부한다.

## 실행 검증 항목

- 사용 슬롯에 입력한 이름 네 글자만 나오며 챕터명이 가려지지 않는지
- 빈 슬롯의 `미사용` 표시가 유지되는지
- 선택·비선택 양쪽에서 `예/아니오`가 버튼 중앙에 표시되는지
- 저장, 덮어쓰기, 불러오기와 Disc 1→2 진행에서 같은 결과가 유지되는지
