# 대사 런타임 검증 기준선

## 현재 결론

사용자 실행 검증에서 원본 시작 주소를 유지한 한국어 대사는 앞부분이 잘리지
않고 올바른 순서와 내용으로 표시됐다. 이 결과로 다음 두 사실을 분리했다.

1. 추출 작업셋의 `u00/ref0000`, `ref0001`, `ref0002` 순서는 맞다.
2. 대사를 압축 재배치하면 아직 목록화하지 못한 원본 주소 소비자 때문에
   앞부분이 잘린다. 현재는 포인터나 시작 주소를 옮기면 안 된다.

현재 `fixed-original-diagnostic` 빌드는 이 기준선을 보존한다. 각 번역을 원본
시작 주소에 그대로 쓰고 포인터는 한 건도 바꾸지 않는다. 단, 긴 번역이 다음
데이터를 덮는 것을 허용하는 의도적 파괴 진단이므로 배포본이나 진행용
이미지가 아니다.

엔트리별 엄격 바이트 경계는
[대사별 검증 안전 슬롯](dialogue-safe-slots.md)이 정본이다. 현재 후보
5,783개 중 1,648개가 이 경계를 넘는다. 17×3 화면 적합 여부와 별도이며,
다음 엔트리 앞의 `0x0000` 워드도 런타임 물리 스트림으로 보호한다.

## 초상화·등장인물명 누락 원인

점·괄호·콤마가 다음 줄로 이동해서 초상화나 이름의 표시 시점이 늦어진다는
가설은 토큰 구조와 맞지 않는다. 각 페이지는 대개 표시 문자보다 먼저 다음과
같은 16비트 제어 토큰을 소비한다.

- `0x9xxx`: `speaker_style` — 화자 표시 상태
- `0xExxx`: `audio` — 음성/이벤트 연동 상태
- `0xFFFB`: 명시적 줄바꿈
- `0x8000` 또는 `0xFFFF`: 페이지/스트림 끝

문장부호는 일반 글리프라서 이미 처리된 선두 제어 토큰을 뒤로 미룰 수 없다.
반면 고정 주소 진단 빌드는 앞 대사가 원본 슬롯을 넘으면 다음 페이지의 선두
제어 토큰을 실제로 덮는다.

unit `0`의 첫 충돌은 다음과 같다.

| 항목 | 값 |
|---|---|
| 초과 대사 | `u00/ref0003` |
| 원본 시작 | `0x0124` |
| 번역 스트림 | 36바이트 |
| 안전 슬롯 | 32바이트 |
| 초과 | 4바이트, 2토큰 |
| 손상 대상 | `u00/ref0004` |
| 손상된 선두 제어 | `speaker_style 0x903F` |

기존 진단 빌드 manifest에서는 unit `0`의 15개 스트림이 당시 용량 판정을
넘어 다음 엔트리 14개를 손상했고, 이 중 12개는 `speaker_style` 또는
`audio` 선두 제어가 손상됐다. 현재 엄격 안전 슬롯과 편집 중인 후보를 다시
결합하면 unit `0` 초과는 19개다. 따라서 현재 관측된 초상화·이름 누락의
직접 원인은 줄바꿈 시점이 아니라 **앞 대사의 바이트 초과로 인한 다음
페이지 제어 코드 손상**으로 판정한다. 빌드 `manifest.json`의
`corrupted_by_overlap_entries[].corrupted_leading_controls`가 각 기대값과
덮인 실제값을 기록한다.

## 제어코드 전수 감사

원본 workset 5,783개와 현재 후보 5,783개를 안정 ID로 결합해 모든 토큰의
원본 위치와 재삽입기의 제어 셸을 다시 검사했다.

- 선두 제어가 있는 엔트리: 5,448개
- 후미 제어가 있는 엔트리: 5,783개
- 내부 조판·이름 토큰이 있는 엔트리: 4,002개
- `speaker_style`: 4,808개
- `audio`: 3,237개
- `page_end`: 4,022개
- `stream_end`: 1,645개
- 제어 셸 파싱 실패: 0개
- 임의 한 글자 본문으로 재인코딩한 선두·후미 raw 불일치: 0개

번역 후보 JSON의 `ko`에는 이 마크업이 없지만, 빌더의
`split_control_shell()`과 `encode_entry()`가 원본 workset에서 선두·후미
제어를 가져와 한국어 본문과 다시 결합한다. 내부 `align`은 현재 줄바꿈에서
`0xFFFB`로 재계산한다. 따라서 제어코드는 재삽입 스트림에 이미 포함된다.

초상화·화자명·분기 밀림은 제어코드가 후보 문자열에 없어서가 아니라, 앞
번역 스트림이 원본 안전 슬롯을 넘어 다음 엔트리에 이미 포함된 선두 제어를
덮기 때문에 발생한다. 제어 마크업을 편집 가능한 `ko`에 복사하면 같은 코드를
두 번 넣을 위험이 있으므로, 편집기에서는 보호 workset과 결합한 실제 인라인
스트림만 읽기 전용으로 표시한다.

## 반각 문장부호 검토

현재 본문 렌더러는 글리프마다 14×14 셀 하나를 사용하고 한 행을 17셀로
계산한다. 공백, 괄호, 점, 콤마도 각각 토큰 하나와 셀 하나를 소비한다.
따라서 글꼴 비트맵만 좁게 그려 “반각처럼” 보이게 만들어도 사용할 수 있는
토큰 수나 줄당 17글리프 제한은 늘어나지 않는다.

실제 용량을 늘리려면 별도 구현이 필요하다.

- 렌더러의 X 증가량을 문자별로 바꾸는 가변폭 훅
- 자주 쓰는 문장부호 두 개를 한 토큰에 그리는 합성 글리프
- 문장 자체의 공백·문장부호 정책을 조정하는 편집 단계

가변폭 훅은 줄 판정, 커서, 선택지와 이름 표시까지 함께 검증해야 한다.
합성 글리프는 제한된 조합에만 효과가 있고 인코더와 매핑 테이블이 추가로
필요하다. 또한 원본 영문·숫자·특수문자 슬롯 `0x000..0x045`,
`0x0E4..0x0E5`는 보호 범위이므로 한글이나 합성 글리프 용도로 재사용하지
않는다. 결론적으로 반각 비트맵 변경은 현재 슬롯 충돌의 해결책이 아니며,
원본 주소 소비자 전수 조사 뒤 별도 PoC로 검토한다.

## 줄바꿈 후속 과제

번역 후보에는 일본어 원문의 짧은 행 구성을 따라 한국어도 일찍 줄을 바꾼
항목이 있다. 현재 진단 빌드는 유효한 17×3 후보 줄바꿈을 그대로 유지한다.
대사 슬롯과 제어 흐름을 안정화한 뒤 다음 정책으로 별도 편집한다.

1. 의미상 고정할 줄바꿈만 표시한다.
2. 나머지 원문 유래 줄바꿈은 합친다.
3. 한국어 띄어쓰기 경계를 우선해 17×3으로 다시 배치한다.
4. 네 줄이 되지만 51글리프 안에 들면 승인된 예외로 단어 내부 분할을
   허용하고 기록한다.
5. 그래도 넘으면 자동 축약하지 않고 안정 ID별 축약 검토 목록에 남긴다.

## unit 21 삽입 상태

챕터 1 뒤의 네메시스 탑재 아스라다와 스고 오사무의 가랜드 관련 구간은
`ALLBIN.BIN` unit `21`의 `voice_event` 68개 엔트리다. unit `0`과 `21`을
함께 인코딩한 진단 파일과 디스크를 생성했다.

unit `21`의 후보 6개는 입력 행 하나가 17글리프를 넘었다. 표시 글리프의
내용과 순서는 바꾸지 않고 기존 줄바꿈 토큰만 제거한 뒤 17칸 단위로 다시
나눴다. `u21/ref0015`는 정확히 51글리프이므로 17×3 단어 분할 예외가
적용됐다. 모든 변경은 파일 빌드 manifest의 `layout_adjustments`에 기록된다.

unit `21`도 원본 고정 슬롯만으로는 완전 진행할 수 없다.

| 항목 | 값 |
|---|---|
| 엔트리 | 68개 |
| 기존 진단 manifest의 안전 슬롯 초과 | 21개 |
| 현재 엄격 안전 슬롯 초과 | 22개 |
| 겹침으로 손상된 다음 엔트리 | 21개 |
| 선두 화자/오디오 제어 손상 | 20개 |
| 첫 초과 | `u21/ref0001`, 6바이트 |
| 첫 손상 대상 | `u21/ref0002` |

즉 u21 번역 데이터는 디스크에 들어갔지만 실행 안정성이 확인된 완성 삽입은
아니다. 사용자 GUI 검증에서는 첫 두 대사의 본문과 `ref0002` 진입 때의
음성·화자 상태를 우선 관찰해야 한다.

## 누락된 선택지와 다음 우선순위

기존 직접 포인터 기반 추출은 unit `0`의 무포인터 페이지 5개를 작업셋에
포함하지 못했다.

| 원본 물리 구간 | 페이지 | 현재 상태 |
|---|---|---|
| `ref0039 → ref0040`, `0x0B8A..0x0BC0` | 시스템 성별: 남성/여성 | 일본어 원본만 보존 |
| `ref0048 → ref0087`, `0x0E18..0x0E2C` | 예/아니오 | 일본어 원본만 보존 |
| `ref0070 → ref0071`, `0x132C..0x1404` | 익스트림 스피드 설명 | 일본어 원본만 보존 |

성별과 예/아니오 메뉴는 번역 후보 JSON에도 없고 현재 진단 이미지에서도
번역되지 않았다. 챕터 1 안정화 직후의 첫 작업은 이 무포인터 페이지에
원본 오프셋 기반 안정 ID를 부여하고 추출·번역·재삽입 경로에 편입하는
것이다.

## 재현 산출물

검증된 원본 위치:

```text
roms/Future GPX Cyber Formula - Aratanaru Chousensha (Japan) (Disc 1).cue
roms/Future GPX Cyber Formula - Aratanaru Chousensha (Japan) (Disc 1) (Track 1).bin
```

unit `0` + `21` 고정 주소 진단 CUE:

```text
work/build/dialogue-chapter01-u21-fixed-original-diagnostic/
  disc1-chapter01-nonrelease.cue
  disc1-chapter01-nonrelease-track1.bin
  manifest.json
```

현재 Track 1 SHA-256:

```text
061c32a605a3d658fb5a6832d552e484be4a34767b7231ce251d91c524f8086c
```

변경 raw sector는 49개이며 계획 밖 섹터 변경은 0개다. 변경 섹터의
Mode 2/Form 1 EDC/ECC와 `START.BIN`·`ALLBIN.BIN` 재추출 일치도 모두
검증했다. GUI 조작과 Lua 실행은 수행하지 않았다.
