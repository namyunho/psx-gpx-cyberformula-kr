# 대사별 검증 안전 슬롯

## 결론

17열×3행은 화면 배치 한도이며 각 대사에 51워드가 예약되어 있다는 뜻이
아니다. Disc 1 대사는 ALLBIN 안에 서로 다른 길이의 16비트 토큰 스트림으로
연속 배치되어 있다. 번역문은 다음 두 조건을 독립적으로 모두 만족해야 한다.

1. 표시 결과가 17열×3행 안에 들어간다.
2. 글리프와 모든 제어토큰을 포함한 인코딩 결과가 해당 엔트리의 검증 안전
   슬롯 바이트 안에 들어간다.

원본이 100바이트인 대사를 124바이트로 바꾸는 일은 17×3에 들어가더라도
안전 슬롯이 124바이트 이상이라는 별도 근거가 없으면 허용할 수 없다.

## 생성 자료

다음 명령은 보호 workset과 원본 ALLBIN을 다시 대조해 JSON과 CSV를 만든다.

```bash
python3 scripts/build_dialogue_safe_slots.py
```

생성 파일은 ROM과 같은 재생성 가능 작업 산출물이므로 `work/` 아래에 두며
Git에는 커밋하지 않는다.

```text
work/analysis/disc1-dialogue-safe-slots.json
work/analysis/disc1-dialogue-safe-slots.csv
```

현재 원본 기준 검증 결과는 다음과 같다.

| 항목 | 값 |
|---|---:|
| 안정 ID | 5,783개 |
| ALLBIN 유닛 | 35개 (`u00..u34`) |
| 원본 토큰 스트림 합계 | 309,654바이트 |
| 엄격 안전 슬롯 합계 | 309,654바이트 |
| 보호하는 2바이트 `0x0000` 간격 | 2,778개, 5,556바이트 |
| 보호하는 비영 간격 | 122개 |
| 유닛 마지막 엔트리 | 35개 |
| 최소/최대 안전 슬롯 | 6/112바이트 |

원본 ALLBIN SHA-256은
`6f61295be0ce2d7d8f38b57badc3b1073e5c16ec3fba5ce898f3368051336a0e`다.
생성기는 workset에 기록된 해시, 각 엔트리의 원본 raw 바이트와 SHA-256,
유닛 기준 주소, 범위 겹침과 16비트 정렬을 전수 검증한다. 하나라도 다르면
자료를 만들지 않는다.

## 엄격한 경계 정책

안전 슬롯은 원본 시작 주소를 바꾸지 않는 `fixed-original-entry-start`
정책의 최대 쓰기 범위다.

| 뒤쪽 물리 상태 | 안전 슬롯 종료 | 이유 |
|---|---|---|
| 다음 엔트리가 바로 시작 | 다음 엔트리 시작 | 원본 종료와 같은 주소 |
| `0x0000` 1워드 간격 | 원본 스트림 종료 | 런타임 커서가 물리 스트림으로 통과하므로 패딩으로 간주하지 않음 |
| 비영 간격 | 원본 스트림 종료 | 무포인터 후속 페이지·이벤트 데이터가 확인됨 |
| 유닛의 마지막 추출 엔트리 | 원본 스트림 종료 | 뒤쪽 유닛 꼬리가 미분류 상태 |

기존 고정 원위치 진단은 다음 엔트리 앞의 영(零) 간격을 임시 용량으로
계산했다. 그러나 저장공간 분석에서 이 워드도 순차 커서가 통과하는 물리
스트림의 일부임을 확인했으므로, 검증 자료와 진단 빌드는 이를 보호하는
엄격 기준을 공통으로 사용한다.

이 정책은 물리적인 덮어쓰기 경계를 검증한다. 초상화, 인물명, 분기와
순차 소비가 실제 플레이에서도 모두 정상이라는 실행 인증은 아니므로 최종
빌드에는 에뮬레이터 실행 QA가 여전히 필요하다.

## 엔트리 필드

JSON은 후보 번역과 같은 안정 ID로 결합한다. 주요 필드는 다음과 같다.

| 필드 | 의미 |
|---|---|
| `id` | `disc1/allbin/u00/event_page/ref0000` 형식의 안정 ID |
| `file_offset`, `unit_offset` | 원본 스트림 시작 주소 |
| `safe_end_file_offset`, `safe_end_unit_offset` | 쓰면 안 되는 첫 바이트 주소 |
| `original_stream_bytes` | 원본 글리프와 제어토큰을 합한 크기 |
| `safe_slot_bytes`, `safe_slot_words` | 허용되는 재인코딩 최대 크기 |
| `gap_after_original_bytes` | 원본 뒤에서 보호하는 물리 간격 |
| `gap_nonzero_byte_count` | 보호 간격 안의 비영 바이트 수 |
| `boundary_kind` | 다음 엔트리·영 간격·비영 간격·유닛 꼬리 구분 |
| `next_physical_entry_id` | ID 순서가 아닌 실제 주소상 다음 엔트리 |
| `protected_target` | 초과할 때 침범하는 대상 분류 |

예를 들어 `u00/ref0003`은 ALLBIN `0x000124`에서 시작하고 검증 안전 종료는
`0x000144`다. 원본과 안전 슬롯은 모두 32바이트다. 편집 결과가 36바이트면
17×3에 들어가더라도 4바이트 초과이며, 바로 다음 물리 엔트리의 선두 제어를
덮을 수 있다.

## 편집기 결합

`scripts/dialogue_layout_editor.py`는 기본적으로 안전 슬롯 JSON을 함께 읽는다.
workset SHA-256과 안정 ID가 맞지 않거나 원본 스트림 크기가 제어 셸과 다르면
실행을 중단한다.

편집기는 각 대사에 다음 값을 동시에 표시한다.

- 원본 스트림 바이트
- 현재 한국어의 예상 재인코딩 바이트
- 검증 안전 슬롯 바이트와 정확한 시작·종료 주소
- 남은 바이트 또는 초과 바이트
- 경계 종류와 보호 대상

현재 예상 바이트에는 표시 글리프뿐 아니라 선두 화자·초상 제어, 음성 제어,
줄바꿈 `0xFFFB`, 페이지 끝 `0x8000` 또는 스트림 끝 `0xFFFF`가 모두
포함된다. 제어토큰은 화면 글리프 칸은 차지하지 않지만 안전 슬롯 바이트는
각각 2바이트 사용한다.

`안전 슬롯 초과만` 필터는 저장공간 초과만 모으며, 목록의 `B` 표시는 해당
엔트리가 현재 안전 슬롯을 넘는다는 뜻이다. 화면 한도 초과 `!`와는 별개의
판정이다.

현재 후보를 보호 제어 셸과 결합한 결과는 정확히 일치 930개, 슬롯보다 작은
엔트리 3,205개, 초과 1,648개이며 최대 초과는 54바이트다. 슬롯보다 작다는
것은 원본 범위 일부를 덮지 않는다는 뜻이지, 남은 바이트를 다른 대사에
재할당할 수 있다는 뜻은 아니다.
