# 프로젝트 진행 기록

기준일: 2026-08-02

대상: PlayStation 일본판 《신세기 GPX 사이버 포뮬러 새로운 도전자》 Disc 1·2

이 문서는 프로젝트 시작부터 현재까지의 작업 흐름, 확정된 구조, 실행 확인과
최신 비배포 빌드 상태를 한곳에 요약한다. 세부 수치와 재현 명령은 각 항목에
연결한 정본 문서를 따른다. 공개 배포판 완성을 선언하는 문서가 아니다.

## 1. 현재 상태

- Disc 1·2의 원본 매체, 파일 시스템, scheduled container와 실행 파일 구조를
  고정하고 전량 추출·재결합 기준선을 만들었다.
- primary·alternate 일본어 글리프 표를 완성하고 Galmuri11 기반 한국어 글꼴과
  직접 u16 글리프 인코딩 경로를 확정했다.
- 본편 `u00..u34`, 무포인터 페이지, 미니게임·코스·머신 설정, 저장 메시지와
  추가 순차·분기 문자열을 통합 편집·재삽입할 수 있다.
- 대사별 고정 슬롯을 넘어도 unit 전체 arena 안에서 남는 공간을 공유하는
  재배치 방식을 확정했고, 대표 unit과 기존 통합판에서 실행 검증했다.
- 4+4 주인공 이름, 화자명, 이름 등록·출신 UI, 저장 화면과 일부 그래픽 버튼을
  별도 기능 브랜치에서 구현했다.
- 최신 반각 시험판은 번역문과 기존 줄바꿈을 바꾸지 않고 공백과
  `! ( ) , . ?`의 화면 진행 폭만 14px에서 8px로 줄인다.
- 그래픽 에셋에 새겨진 문자와 음성 전용 장면의 자막 오버레이는 아직 본 작업
  범위에 들어가지 않았다.

## 2. 원본 매체와 도구 환경

지원 원본은 일본판 멀티 BIN/CUE 두 세트다.

| 항목 | Disc 1 | Disc 2 |
|---|---:|---:|
| 부트 실행 파일 | `SLPS_019.58` | `SLPS_019.59` |
| Track 1 형식 | `MODE2/2352` | `MODE2/2352` |
| Track 1 크기 | 602,020,272바이트 | 602,081,424바이트 |
| SHA-256 | `35e43fba9c5ffc39ab805adbc42f13ec3198c888c1c1e9e651408409e041b2a9` | `a80c5efdff17d9363ee3990fba0e02a7e872a296f6882b2a7743de90cb52d691` |

원본은 `roms/`, 추출·분석·빌드 결과는 `work/`에 두며 Git에는 넣지 않는다.
빌드 전에 Track 1과 CUE, 오디오 Track 2~4를 모두 검증한다.

역공학 도구는 다음처럼 상호보완적으로 사용한다.

- IDA Pro/idalib: MIPS 명령, 함수 경계, 짧은 루틴과 xref 확인
- Ghidra: 긴 제어 흐름, 포인터 전달과 디컴파일 교차검증
- PCSX-Redux: GDB 서버, RAM/VRAM, GPU Logger, 워치포인트와 실제 실행 확인
- Kaitai Struct Compiler: 선언적 바이너리 구조와 parse/build 왕복 검증
- armips와 Capstone: MIPS 패치 조립과 독립 디스어셈블 검산

DuckStation은 더 이상 작업·검증에 사용하지 않는다. PCSX-Redux GUI 이동과 Lua
실행은 사용자가 재현 위치를 준비하고 신호를 준 뒤에만 수행한다. 자세한 환경은
[`reverse-engineering-mcp.md`](reverse-engineering-mcp.md)를 따른다.

## 3. 구조 분석과 전량 추출

첫 단계에서는 ROM을 수정하지 않고 Disc 1의 파일 로더와 schedule을 분석했다.

- ISO 파일 16개, 실행 파일 record 19개와 load descriptor 164개
- scheduled 파일 11개, 재결합 state 1,935개
- offset-directory child 4,876개
- primary·alternate 글꼴, 초상 625개, 그래픽 관련 state 1,739개
- XA 33개, VAB 81 bank/1,663 sample, CDDA 3개, MDEC 영상 2개

추출·재결합은 무수정 round-trip, 파일 크기와 해시로 검증했다. ISO 파일 좌표,
raw 2352바이트 sector, PS-X EXE 파일 오프셋과 runtime 주소는 서로 다른
좌표계로 관리한다. 기준선은 [`reverse-engineering-baseline.md`](reverse-engineering-baseline.md),
추출 결과는 [`disc1-extraction.md`](disc1-extraction.md)에 있다.

## 4. 글꼴 판독과 한국어 글꼴

게임 글꼴은 TIM이 아니라 `START.BIN`의 고정 길이 압축 레코드다.

| 항목 | primary | alternate |
|---|---:|---:|
| 정의 글리프 | 1,229 | 1,484 |
| 셀 | 14×14px | 14×14px |
| 저장 | 3bpp, 74바이트/글리프 | 3bpp, 74바이트/글리프 |

사용자가 실제 게임 색상에 맞춰 만든 `primary/alternate ... modify` 아틀라스를
기준으로 전 슬롯을 판독했다. primary 한자 배열은 단순 빈도순이 아니라
JIS X 0208 제1수준 계열 정렬과 맞는다. 글꼴의 3bpp 명암 index는 CLUT를 거쳐
밝은 본문과 회색 외곽선·그림자로 보인다.

한국어 글꼴은 Galmuri11 TTF 12px 입력을 채택했다. 실제 잉크는 최대 약
11×11px로 14×14 셀 안에 들어간다. 영문·숫자·필수 기호 슬롯을 한글 배정에
사용하지 않고, 채택 번역 코퍼스에 필요한 문자만 primary 표에 결정적으로
배치한다. 대사 토큰은 새 index로 직접 재인코딩하므로 역사적인 리맵 캐시 훅은
현재 빌드 경로에서 사용하지 않는다.

세부 구조는 [`font-format.md`](font-format.md), 글꼴 프로필은
[`korean-font.md`](korean-font.md), 직접 인코딩 결정은
[`hangul-storage-encoding.md`](hangul-storage-encoding.md)에 기록했다.

## 5. 대사 추출, OCR과 번역 협업

`ALLBIN.BIN`에서 직접 참조되는 대사 5,783개를 안정 ID
`disc1/allbin/u**/.../ref****`로 추출했다. 이후 직접 포인터 표에 없던
무포인터 선택·대사 페이지 83개를 추가했다. 원문, raw u16, 제어토큰, 화자,
초상, 음성, 페이지 대기와 종료 정보를 보호 필드로 분리해 round-trip 가능한
JSON으로 관리한다.

초기 일본어 OCR 오인식은 수정 아틀라스와 글리프 코드를 대조해 고쳤다. 외부
AI 번역용으로는 전체 분석 JSON 대신 안정 ID, 일본어 원문, 최대 글리프와
번역 필드만 담은 간결한 파일을 만들었고, 별도 용어집 후보도 생성했다. 번역은
기계 후보와 수작업 교정이 섞여 있으며 최종 언어 검수는 계속 필요하다.

작업 형식과 제어코드는 [`dialogue-extraction.md`](dialogue-extraction.md),
외부 협업 형식은 [`translation-candidate-handoff.md`](translation-candidate-handoff.md)를
따른다.

## 6. 안전 슬롯에서 unit 공용 arena로

초기 고정 위치 삽입에서는 대사가 잘리거나 다음 화자·초상·분기 시점이 밀려
프리즈하는 문제가 있었다. 원인은 대사마다 17×3의 독립된 빈 공간이 있는 것이
아니라, 가변 길이 텍스트와 제어 요소가 unit의 연속 영역을 공유하는 구조였기
때문이다.

먼저 5,783개 대사의 원본 고정 안전 슬롯을 추출해 편집기에 표시했다. 이후
`u00`과 `u21`에서 다음 규칙을 시험했다.

1. 개별 대사는 원래 슬롯보다 길거나 짧아질 수 있다.
2. unit의 전체 대사·제어 데이터는 원본 arena 총량을 넘지 않는다.
3. 화자·초상·음성·분기·종료·숨은 소비자는 대사 사이의 의미 순서를 보존한다.
4. 모든 직접·숨은 참조를 새 위치로 다시 연결한다.
5. 남는 끝 영역은 명시적인 패딩으로 원본 unit 크기에 맞춘다.

사용자 실행 검증에서 `u00/u21`의 대사, 초상, 화자명, 음성, 분기와 종료가
정상 작동했다. 같은 불변식을 `u00..u34`로 확대했고, 이후 통합판은 사용자
진행 기준 제2장 종료까지 크래시 없이 작동했다. 이는 모든 후속 분기와 최신
빌드 전체의 실행 통과를 뜻하지 않는다.

고정 슬롯은 [`dialogue-safe-slots.md`](dialogue-safe-slots.md), 실험과 승격은
[`unit-dialogue-pool-experiment.md`](unit-dialogue-pool-experiment.md)에 있다.

## 7. 통합 대사 편집기

Python/Tk 기반 편집기는 그래픽 에셋을 제외한 폰트 문자열을 한 화면에서
다룬다. 현재 독립 번역 기준 7,059행이며 다음 범위를 포함한다. 최종전 물리
미러 70개와 짧은 경기 미러 6개는 각 정본 행에서 자동 생성한다.

- 본편 직접 대사와 무포인터 페이지
- 추가 순차 이벤트·경기·미니게임·저장 문자열
- 미니게임 규칙, 코스 설명, 머신 설정과 모터홈 선택
- 이름 등록 UI, 고정 주인공명과 화자명

편집기는 원본 안전 슬롯과 unit 공용 총용량을 따로 표시하고, 제어토큰을
시각화한다. 17글리프 초과, 51글리프 초과, 짧은 줄, 저장 공간 초과 필터와
찾기/일괄 바꾸기를 제공한다. 편집 방침은 한 페이지 최대 3줄을 유지한다.
macOS에서는 `대사-편집기.command`로 실행할 수 있다.

자세한 사용법은 [`dialogue-layout-editor.md`](dialogue-layout-editor.md)에 있다.

## 8. 추가 폰트 문자열과 분기 감사

직접 포인터 중심 추출 밖의 물리 gap을 다시 조사해 다음 716개를 별도
workset으로 확정했다.

| 종류 | 수 |
|---|---:|
| 순차 이벤트·경기 문자열 | 616 |
| `u38` 추가 미니게임 문자열 | 73 |
| `u39` 저장·불러오기 메시지 | 27 |

특수 화면 file build는 `u38` 미니게임 322개와 `u43` 코스·머신 설정 71개,
합계 393개를 정적 주입한다. 더 넓은 조사 workset에는 고정 리터럴과 런타임
단어가 포함되므로 “조사 행 수”와 “정적 주입 엔트리 수”를 같은 수로 보지
않는다.

2026-08-02 분기·커맨드 재감사에서는 다음 29개 누락을 확정했다.

- `u09` 주크박스의 `キャンセル` 1개
- `u28` fall-through 경기 페이지 8개
- `u43` 머신 설정 도입·설명·확인 분기 20개

전체 `FFFD`, `D002`, `D003` 분기를 재열거한 결과, 실행이 확인된 미번역
커맨드는 위 `취소` 한 건이었다. 이후 `u30..u34`에 반복되는 최종전 후보는
실제로 14페이지×5 overlay=70개임을 바로잡았고, 실행 화면과 정적 참조를
확인해 패치 대상으로 승격했다. 세부 근거는
[`unindexed-font-text.md`](unindexed-font-text.md),
[`special-screen-font-text.md`](special-screen-font-text.md),
[`branch-command-text-audit.md`](branch-command-text-audit.md)에 있다.

## 9. 이름 등록과 캐릭터 이름

초기 고정 이름은 성 2글자 `시바`, 이름 4글자 `세이치로`로 만들었다. 이후
별도 `feature/player-name-4x4` 브랜치에서 원본 3+3 입력 구조를 4+4로
확장했다.

- 성 4글자와 이름 4글자의 입력·저장·게임 내 표시
- 여덟 번째 글자 입력 뒤 결정 상태로 이동
- 성·이름 간격과 입력 표시 위치 보정
- 최종 확인 화면의 4+4 표시
- 입력한 이름을 대사 `{name:surname}`·`{name:given}` 소비자에 연결
- 출신 설명과 `균형형/기술형/파워형` UI, 그림자와 버튼 정렬 보정

사용자는 8글자 이름이 실제 게임 안에서 정상 출력되는 것을 확인했다. 입력
폼의 자동 결정과 간격도 후속 실행에서 통과했다. 최종 확인 화면의 세부 좌표와
취소 후 커서 복귀, 출신 설명·버튼의 최종 시각 품질은 기능 브랜치에서 더
검수할 항목으로 남아 있다.

화자명 표에는 인물뿐 아니라 아스라다·네메시스, 아나운스와 역할명까지 34개를
용어집 표기로 등록했다. 이름 구조의 정본은
[`character-name-layout.md`](character-name-layout.md)다.

## 10. 저장 화면과 미니게임 UI

저장·불러오기는 일반 대사와 다른 소비자를 함께 쓴다.

- `u39`의 저장 문장 27개
- 실행 파일의 슬롯 이름·챕터·상태 메타데이터
- `OUTSIDE.BIN` 4bpp `예/아니오` 버튼 그래픽

누락된 `저장 중입니다`, `완료되었습니다`, 덮어쓰기 문구를 고치고 빈 슬롯
표시와 슬롯 메타데이터를 분리했다. 긴 4+4 이름이 챕터 열을 침범하지 않도록
저장 목록에는 이름 네 글자만 표시하도록 설계했다. `예/아니오`는 원본 4bpp
행 간격을 바로 계산해 버튼 중앙에 넣었다. 현재 화면 이름 표시의 최종 실행
확인은 남아 있다. 자세한 내용은
[`save-screen-localization.md`](save-screen-localization.md)에 있다.

요리 미니게임의 규칙 제목·설명은 폰트 문자열로, 선택 버튼은 그래픽으로
분리했다. 그래픽 버튼 변경은 `feature/minigame-localization` 브랜치에
격리돼 있으며 추가 시각 수정 후 main 병합을 판단한다.
## 11. Disc 2 분석과 공통 빌드

Disc 1 종료 후 원본 Disc 2로 교체했을 때 한글 모양의 글리프가 뒤섞인 현상을
계기로 Disc 2를 Disc 1과 같은 방식으로 전량 조사했다. 결론은 두 디스크가
같은 게임 콘텐츠·대사·글꼴을 공유하고 다음만 다르다는 것이다.

- 부트 파일명 `SLPS_019.58` / `SLPS_019.59`
- `START.BIN +0x8ACC`, `+0x3D1000`의 Disc 식별값 0 / 1
- Disc 2의 26-sector 간격과 그 뒤 파일의 실제 LBA

Disc 1 변경분만 Disc 2 원본에 이식하고 Disc 2 고유 바이트와 LBA를 보존하는
빌더를 만들었다. 사용자는 패치 Disc 2로 교체한 뒤 정상 진행과 한국어 대사
출력을 확인했다. Disc 2 전편의 모든 분기·특수 화면을 통과했다는 증거는 아니다.

이후 대사·폰트·UI·실행 코드의 공통 변경은 Disc 1·2 이미지를 같은 승인
입력에서 함께 만들고, 각 원본과 Track 해시에 귀속해 따로 검증한다. 정본은
[`disc2-reverse-engineering-baseline.md`](disc2-reverse-engineering-baseline.md)다.

## 12. 반각 공백·문장부호

한국어 대사에서 전각 공백과 문장부호 간격이 지나치게 넓어 보이는 문제를
해결하기 위해 `feature/halfwidth-dialogue-renderer` 브랜치를 만들었다.

번역 JSON과 기존 줄바꿈은 수정하지 않는다. `sub_80032704`의 논리 17칸
카운터도 그대로 두고 공백과 `! ( ) , . ?` 뒤의 다음 목적지 좌표만 6px
당긴다. 결과적으로 대상 문자는 8px, 나머지 글리프는 14px를 진행한다.

2026-08-03에는 이름 치환 경로가 앞선 반각 누적 좌표를 건너뛰어 뒤 글리프와
겹치는 회귀를 수정했다. `{name:surname}`·`{name:given}` 글리프는 누적 좌표를
이어받고 현재 논리 위치를 저장하지만 반각 후보에는 들어가지 않아 계속 14px를
진행한다. 이름 치환 116개 중 같은 행 앞쪽에 반각 문자가 있는 직접 영향 후보는
60개다.

armips 패치는 원래 함수 범위 `0x80032704..0x800329B8` 안에 들어가며,
Capstone 독립 디스어셈블로 MIPS load/branch delay와 변경 범위를 검산했다.
`START.BIN`, `ALLBIN.BIN`, `OUTSIDE.BIN`, 대사 u16과 제어토큰은 직전 파일
빌드와 바이트 단위로 같다. 구현은
[`halfwidth-text-renderer.md`](halfwidth-text-renderer.md)에 기록했다.

## 13. 최신 비배포 빌드

2026-08-09 통합판에 이름 등록·어빌리티·최종 확인, 저장과 요리 미니게임의
그래픽 라벨 중심 보정을 추가하고, 동일 파일 빌드에서 Disc 1·2를 각각 만들었다.
버튼 배경과 라벨이 별도 스프라이트인 경로는 저장 사각형 중앙 대신 원본 일본어
비투명 픽셀 중심을 기준으로 삼는다.

| 항목 | Disc 1 | Disc 2 |
|---|---:|---:|
| Track 1 크기 | 602,020,272 | 602,081,424 |
| 변경 raw sector | 1,137 | 1,137 |
| SHA-256 | `adbde780405306f46592aae9347eb4b3854c21e1023a3b170808e3d158d69de7` | `c5ae02a24e19602ef98804e39920a016d54a0366a58ece5e1eb227ba9b72fae7` |

두 이미지가 통과한 정적 검증:

- 해당 Disc의 원본 Track 1~4와 CUE 식별
- 출력 폴더에 Track 2~4 원본 오디오를 바이트 그대로 복사한 자체완결형 CUE
- 저장소 루트에서 `dumpsxiso`로 CUE를 직접 열어 전체 파일 추출 성공
- 원본과 출력의 ISO root 위치·크기 동일성
- Disc별 부트 파일명, LBA와 `START.BIN` 식별 바이트 보존
- 선언된 Expected Write와 실제 변경 sector 일치
- 변경 Mode 2 Form 1 sector의 EDC/ECC 재계산
- 완성 Track에서 패치 파일 재추출과 입력 해시 일치
- 요리 미니게임 버튼 8개가 확인된 4bpp 사각형만 변경하고 CLUT를 보존
- 이름 UI의 공유 `결정`을 포함한 고유 라벨 9개, 저장 라벨 2개와 요리 라벨
  8개의 교체 합성 중심이 원본 기준에서 허용 오차 이내인지 검증
- 타이틀 384×256 index 평면만 변경하고 원본 256색 CLUT를 바이트 단위로 보존
- 4+4 이름의 정적 코드 표를 저장 화면 패치가 옮기는 구성을 manifest에 명시하고,
  나머지 4+4 코드·데이터 변경을 보존
- 전체 261개 검사와 두 디스크 독립 재검증 통과

상태는 `static-verification-passed-runtime-validation-required`다. 현재 반각
빌드 자체의 화면 검증은 아직 하지 않았다. PCSX-Redux에서 새 타이틀과 요리
미니게임 선택 버튼을 우선 확인하고, 일반 대사·연속 문장부호·공백·이름 입력과
컨트롤러 아이콘도 함께 회귀 확인해야 한다.

통합 폰트 번역 편집기도 같은 반각 규칙을 반영했다. 행마다 기존 17개 논리
글리프 한도와 238px 화면 폭을 따로 표시하고, 공백·`! ( ) , . ?` 다음 글자를
8px 진행 폭에 맞춰 당겨 그린다. 반각화는 저장 토큰 수나 17열 자동 줄바꿈을
바꾸지 않으므로 기존 안전 슬롯·unit 총량 판정과 자동 배치는 그대로 유지한다.

새 이미지의 독립 검증이 끝난 뒤 `work/build/`의 이전 Disc 1·2 전체 이미지와
짝 CUE 및 남아 있던 과거 디스크 빌드 디렉터리를 휴지통으로 옮긴다. 현재 기준은
2026-08-09 버튼 중심 보정 검증본 한 세트씩이다. 원본 `roms/`, 파일 단위 중간
빌드와 분석 자료는 삭제하지 않았다.

## 16. 남은 작업

1. 목적별 기능 브랜치를 검토해 main으로 순차 통합하고, 깨끗한 checkout에서
   Disc 1·2 공통 빌드를 재현한다.
2. 최신 반각 Disc 1·2를 PCSX-Redux에서 콜드 부팅해 대표 화면과 행 전환을
   확인한다.
3. 저장·불러오기, 4+4 이름 최종 확인, 미니게임·코스·머신 설정과 신규 분기를
   우선 회귀 검증한다.
4. 통합 편집기에서 남은 번역의 의미·용어·축약과 자연스러운 줄바꿈을 사람이
   계속 교정한다.
5. 마지막 단계에서 타이틀·챕터 카드·버튼 등 그래픽 에셋에 새겨진 문자를
   현지화한다.
6. 음성만 재생되는 장외 아나운서 장면의 자막 오버레이 가능성을 별도 PoC로
   판정한다.
7. 전편 QA 뒤 원본 전체가 아닌 차분 패치를 만들고, 적용 결과가 검증한 목표
   이미지와 일치하는지 확인한다.

새 미번역 폰트 문자열이나 새 소비자가 실행 중 발견되면 “그래픽 제외 폰트
문자열 완료” 판정을 다시 열고, 동일한 추출·제어 보존·글리프·저장 공간·Disc
1·2 Expected Write 검증 절차에 편입한다.
