# 첫 한글 가시성 PoC

> 이 문서는 2026-07-12 Galmuri14로 본문 렌더 경로를 처음 증명한 역사적
> 기록이다. 현재 확정 글꼴 Galmuri11의 교체 PoC는
> [`galmuri11-font-poc.md`](galmuri11-font-poc.md)에서 별도 판정한다.

## 목표와 현재 상태

목표는 한글 한 글자가 원본 Disc 1의 본문 데이터, 내장 폰트 공급 경로, 원본
14×14 렌더러를 거쳐 실제 화면에 표시되는지 확인하는 것입니다.

다음 정적·RAM·화면 검증을 완료했습니다.

- [x] TTF `Galmuri14 Regular`에서 `한`을 14×14, 3bpp 74바이트로 생성
- [x] 대사 시점에 안전한 완전한 빈 글리프 슬롯 `0x4CD` 확정
- [x] 첫 대사 토큰을 `0x03B7`에서 `0x04CD`로 바꾸는 동일 크기 빌드
- [x] 수정 Track 1에서 `START.BIN`과 `ALLBIN.BIN`을 재추출해 해시 검증
- [x] 수정 이미지에서 `한`의 자형·위치와 주변 표시 확인
- [x] 원본 글리프의 3bpp 색상값을 따라 흰색 한글로 수정
- [x] 첫 대사 전체의 2줄 한국어 표시와 스크린샷 확인

최소 가시성 게이트는 통과했습니다. 이 결과는 본문 데이터와 글리프가 원본
14×14 렌더 경로를 통해 화면에 도달함을 증명하지만, 전체 한글 슬롯·인코딩
수용량은 증명하지 않습니다.

## 표적

첫 단계에서는 처음 확인한 대사의 `憧`을 `한`으로 바꿨습니다.

```text
（ようやくここまできた…憧れの
```

| 항목 | 값 |
|---|---:|
| 원본 텍스트 토큰 | `ALLBIN.BIN + 0x6E = 0x03B7` |
| PoC 텍스트 토큰 | `0x04CD` |
| PoC 글리프 | `START.BIN + 0x30342` |
| PoC 글리프 RAM | `0x8002AD42` |
| 글리프 크기 | 74바이트 |

대사 시점의 파일/RAM 연속 일치는 `START.BIN + 0x1A000`부터
`0x16393`바이트입니다. `0x4CD` 슬롯의 끝은 이 범위 끝보다 7바이트 앞이므로
한 슬롯 전체가 안전하지만, 다음 슬롯은 실행 코드와 겹칩니다.

스크린샷용 두 번째 단계에서는 같은 대사 전체를 다음과 같이 교체했습니다.

```text
（드디어 여기까지 왔다…
꿈의 팀 「스고 그랑프리」）
```

각 줄은 원본과 같은 15칸 안에 들어갑니다. 공백은 빈 `0x4CD` 슬롯을
재사용하고, 괄호·낫표·말줄임표는 원본 글리프를 유지했습니다. 한글 18자는
이 화면에서 더 이상 필요하지 않은 원본 일본어 슬롯을 임시로 덮어썼습니다.
이 매핑은 화면 PoC 전용이며 본 구현의 인코딩 테이블로 승격하지 않습니다.

## 색상값 수정

첫 `한`은 켜진 픽셀에 3bpp 값 `7`을 사용해 검정색으로 표시됐습니다. 원본
일본어 글리프는 주 획에 값 `1`을 사용하고 경계 명암에 값 `2..6`을 섞습니다.
단색 한글의 켜진 픽셀을 값 `1`로 바꾸자 원본 본문과 같은 흰색으로
표시됐습니다. 따라서 현재 본문용 단색 한글의 기준값은 `1`입니다.

## RAM 사전 실험

실행 중 RAM의 원본 `0x03B7` 글리프가 디스크의 해당 74바이트와 완전히
일치함을 확인했습니다. 이후 `gdb_write.py`로 같은 주소와 `0x0072` 슬롯에
`한` 글리프를 써서 재읽기 검증까지 통과했습니다. 당시 화면은 이미 VRAM에
그려진 대사를 유지하고 있어 기존 픽셀은 갱신되지 않았습니다.

RAM 실험 결과는 다음 두 가지를 구분했습니다.

- 증명됨: 폰트 RAM 주소 계산과 74바이트 주입 경로
- 이후 이미지 검증으로 증명됨: 새로 렌더링된 본문 화면에서의 실제 한글 표시

## 재현 빌드

다음 명령은 원본에서 같은 크기의 중간 파일을 만들고, 로컬 Track 1 복사본의
변경 섹터 두 곳만 수정합니다. 원본 오디오 트랙은 PoC CUE와 같은 로컬 작업
폴더로 복사하며 원본에는 쓰지 않습니다.

```powershell
$env:PYTHONPATH = "work/pydeps"
python scripts/build_font_poc.py `
  --start-bin work/disc1/START.BIN `
  --allbin work/disc1/ALLBIN.BIN `
  --ttf font/font-12345a7f7565e4fe.ttf `
  --full-dialogue `
  --intensity 1 `
  --output-dir work/poc-full/files `
  --track1 "roms/Future GPX Cyber Formula - Aratanaru Chousensha (Japan) (Disc 1) (Track 1).bin" `
  --track-output work/poc-full/disc1-full-track1.bin `
  --source-cue "roms/Future GPX Cyber Formula - Aratanaru Chousensha (Japan) (Disc 1).cue" `
  --cue-output work/poc-full/disc1-full.cue `
  --allow-invalid-edc
```

검증된 결과:

| 산출물 | SHA-256 |
|---|---|
| PoC `START.BIN` | `2FB35A432462BA1550F7BA5BA1D341E5E8377D4F989B0A2DC4CB7185F519162A` |
| PoC `ALLBIN.BIN` | `A521A3EF428E30AE30494EFF0432C9C11544B4B38D4C3487A544B31E202856EF` |

변경된 raw 섹터는 LBA 277, 279~284, 311, 9919입니다. 이 PoC 이미지는 변경
섹터의 EDC/ECC를 아직 재계산하지 않으므로 **DuckStation 검증 전용**입니다.
실기, CD-R, ODE 또는 배포 빌드에는 사용하지 않습니다.

## 통과 기준과 남은 범위

첫 대사에서 흰색 한글 두 줄이 올바른 위치와 자형으로 표시됐고 주변 대화창도
깨지지 않았습니다. 사용자가 해당 화면의 스크린샷을 촬영해 화면 판정을
완료했습니다.

이 PoC가 통과해도 다음 항목은 별도로 남습니다.

- 전체 한글 코드·슬롯 공급 방식
- 수백 자 폰트의 저장 위치와 적재 경로
- 전체 번역문 수용량과 포인터 재배치
- 이름 선택 화면의 고정 이름 표시·저장·재표시
- 실기용 Mode 2 Form 1 EDC/ECC 재계산
