# PS1 글꼴 포맷 분석

## 확정 결과

대사 글꼴은 표준 TIM 이미지가 아니라 `START.BIN` 안의 고정 길이 압축
글리프 테이블입니다.

| 항목 | 값 |
|---|---:|
| 파일 기준 주소 | `START.BIN + 0x1A000` |
| RAM 기준 주소 | `0x80014A00` |
| 글리프 크기 | 14×14픽셀 |
| 픽셀 깊이 | 3bpp, 값 0~7 |
| 글리프당 크기 | 74바이트 |
| 픽셀 비트 순서 | little-endian, LSB 우선 |
| 글리프 선택 | `(token & 0x0FFF) * 74` |

14×14픽셀은 196픽셀이며 3bpp로 588비트가 필요합니다. 따라서 한 글리프는
74바이트이고 마지막 4비트는 패딩입니다.

## 실행 코드 경로

- `0x80032704`: 현재 텍스트 토큰 선택, 글리프 인덱스 계산, 화면 좌표 계산
- `0x80032434`: 74바이트 3bpp 글리프를 14×14 출력 영역으로 해제
- `0x8003259C`: 같은 입력 포맷을 사용하는 다른 출력 폭의 변형 해제 루틴

`0x80032704`는 일반 대사 상태에서 `0x80014A00 + index * 74`를 글리프
원본으로 사용합니다. `0x80032434`는 3비트 픽셀을 순서대로 읽어 게임의
4bpp 작업 표면에 배치합니다.

`START.BIN + 0x1A000`과 `0x80014A00`의 대응은 Disc 1 대사 시점 RAM 덤프와
파일 조각의 바이트 일치, 그리고 로더 배치 차이 `-0x5600`으로 확인했습니다.

## 화면 교차 검증

`data/glyph-map.json`에 기록된 29개 토큰을 이 포맷으로 직접 렌더링했습니다.
괄호, 줄임표, 히라가나, 가타카나, 한자 `憧`이 실제 대사 화면 및 판독 문자열과
일치했습니다. 따라서 토큰 값, 글리프 테이블 위치, 비트 순서, 글리프 크기를
하나의 독립된 화면 표본으로 교차 검증한 상태입니다.

재현 명령:

```powershell
$env:PYTHONPATH = "work/pydeps"
python scripts/psx_font.py work/disc1/START.BIN `
  --offset 0x1A000 `
  --glyph-map data/glyph-map.json `
  --output work/font-known.png
```

## 한국어 PoC에 주는 의미

한국어 PoC는 다음 최소 경로로 만들 수 있습니다.

1. 사용하지 않는 글리프 슬롯을 확정한다.
2. 14×14, 3bpp 한글 글리프를 `pack_glyph()`로 인코딩한다.
3. 해당 슬롯의 74바이트를 교체한다.
4. 시험 대사의 토큰을 새 슬롯 번호로 바꾼다.
5. 수정된 파일을 별도 작업 이미지에 재삽입해 에뮬레이터에서 검증한다.

아직 사용하지 않는 슬롯과 전체 글리프 수는 확정하지 않았으므로, 현재 단계에서는
원본 테이블을 직접 수정하지 않습니다.
